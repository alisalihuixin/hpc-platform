1. 背景与目标

1.1 观察到的问题

  • 算力分散在多个调度器（Slurm / PBS / K8s）上，入口各异：用户要记不同集群的登录方式与命令。
  • 用量数据散落在各调度器内部，口径不一致，无法横向汇总。
  • 成本无法归属：没有人能回答「上个周期 A 项目用了多少算力、折合多少成本」。
  • 配额靠口头约定与表格维护，超用不可见，事后才发现。

1.2 受影响用户与时刻

  • 科研 / 工程用户：提交作业时（不知去哪个集群、要排多久），以及需要了解自己用量时。
  • 集群 / 平台管理员：分配配额、核对用量、出成本报表时。
  • 成本 / 财务负责人：需要按项目分摊算力成本时。

1.3 产品决策

在既有调度器之上建统一管理面。调度算法（排队、优先级、抢占）仍由 Slurm / PBS / K8s 负责，平台不重复实现；平台负责打通这条链路：

统一入口提交 → 统一视图监控 → 统一口径计量 → 归属到账户 / 项目的成本核算 → 周期账单。

1.4 目标（以可观测结果表述）

  • 用户可在平台内完成一次「提交作业 → 查看结果」的完整流程，全程无需登录具体集群。
  • 任意时刻可查到「某账户在某周期内的用量与成本」，且能下钻到具体作业。
  • 配额超限时，提交被明确拒绝，并说明原因与恢复方式，而非静默失败。
不写定量目标（如「效率提升 30%」）：无任何基线数据支撑，写出来即编造。若后续有实测数据再补充。

2. 范围

2.1 P0：最小完整旅程

入口条件：用户已登录，且归属于某个账户（项目）。

  1. 用户选择集群 / 队列，填写作业参数（或套用模板）并提交；
  2. 平台将作业提交到对应调度器，并展示「排队中 / 运行中」状态；
  3. 用户可查看作业日志与输出位置；
  4. 作业结束（完成 / 失败 / 取消），平台记录该作业的用量；
  5. 用量按单价折算为费用，计入当前账期，归到提交者所在的账户；
  6. 账期结束后生成账单；用户可查看自己的用量与费用明细。

完成证据：用户能看到作业的最终状态，以及该作业对应的一条用量与费用记录。

最重要失败路径的恢复：提交被拒（配额不足 / 参数非法 / 调度器不可达）时，用户应看到可区分的原因与下一步动作（调整参数、申请配额、稍后重试），且已填写的参数不丢失。

2.2 P1：支撑能力

  • 作业模板与批量提交；队列切换与重跑；
  • 通知（站内 / 邮件）；
  • 报表导出；
  • 对账与调整单（账单有异议时的冲正流程）；
  • 审计日志查询。

2.3 本期明确不做

  • 不做 自研调度器（排队、抢占、公平分享算法）；
  • 不做 对外收费能力（在线支付、发票、开票主体）——本期定位是内部成本核算，不产生真实资金流转；
  • 不做 跨集群自动迁移作业。

3. 产品模型

3.1 角色

角色主要职责数据边界
平台管理员接入集群、维护队列与全局单价、处置异常全部集群与账户
成本管理员定价、出账、对账、调整全部账户的用量与账单（只读作业详情）
账户负责人管理本账户成员与本账户配额仅本账户
普通用户提交与管理自己的作业仅自己的作业与自己的用量
M1 已交付 admin / user 两个角色。本 PRD 要求扩展为上表四类； 与既有两角色的对应关系（例如 admin 是否直接等同「平台管理员」）TBD。

3.2 核心对象

对象说明关键属性
账户 Account成本归属单元，对应项目或课题组名称、负责人、成员、状态
集群 Cluster一个被接入的调度器实例类型（Slurm/PBS/K8s）、连接状态
队列 Queue集群下的可提交目标（分区 / 队列 / namespace）可用资源规格、归属集群

3.3 生命周期状态

作业状态

「已提交」是平台侧瞬态；一旦调度器受理即进入「排队中」或「运行中」。终态为：已完成 / 失败 / 已取消 / 提交失败，终态不可再变更。

账单状态

状态含义可执行操作
草稿账期内实时累计，未固化随用量变化自动更新
已出账账期结束，金额已固化查看、提出异议、导出
有异议账户负责人已提出问题，待成本管理员处理补充说明、等待调整
已关账异议已解决或账期结束无异议仅查看与导出

账期长度与出账时点：TBD（见 第 6 节）。

4. 功能需求

以下 FR 按模块组织。P0 为最小旅程必需，P1 为支撑能力。

FR-01 集群与队列接入 P0

目的
让管理员把已有调度器纳入平台，并定义用户可提交的目标。
触发
平台管理员新增或更新一个集群 / 队列。
处理规则
  • 接入时必须声明调度器类型（Slurm / PBS / K8s）与访问凭据；凭据仅平台管理员可见，其他角色不可读取。
  • 接入后平台需能读取该集群的队列列表；队列可作为独立提交目标的粒度 TBD（分区 / 队列 / namespace 三者选型）。
  • 「连接状态」需可察：正常 / 不可达。不可达期间该集群的队列不出现在提交流程中。
结果与状态变化
集群 / 队列出现在提交界面的可选列表中；不可达时自动从可选列表移除并给出提示。
异常
凭据失效 → 连接状态置为不可达，并通知平台管理员；已提交的历史作业不受影响，仍可查看。

FR-02 作业提交 P0

目的
用一个统一入口把作业投递到不同调度器，用户无需感知底层差异。
触发
普通用户在某账户下，选择队列并填写参数后提交。
处理规则
  • 提交前依次校验：账户归属有效 → 配额未超 → 参数合法 → 目标队列可用。任一不通过即拒绝，且不落作业。
  • 校验失败的原因必须可区分，至少覆盖：配额不足、参数非法、队列不可用、调度器不可达。
  • 提交成功后，平台记录提交者、所属账户、目标队列与全部参数，作为后续计量与归属的依据。
结果与状态变化
作业进入「已提交」→「排队中 / 运行中」；提交失败则落为「提交失败」终态并保留原因。
字段
字段必填说明
作业名是用户可读标识
目标队列是来自 FR-01 的可用队列
资源需求是核数 / 内存 / GPU 数 / 预计时长
启动命令是待执行的命令行
所属账户是决定计量归属，默认取用户主账户
异常
提交过程中调度器超时：平台不得重复投递；应标记为「提交失败」并允许用户一键重试，重试前需确认原作业确未在调度器侧创建。假设 调度器支持幂等标识或可按名称回查。

FR-03 作业监控与日志 P0

目的
用户不必登录集群即可判断作业进展与结果。
触发
用户从「我的作业」列表进入详情。
处理规则
  • 列表支持按状态、队列、时间范围筛选；状态取自调度器，平台不做二次推断。
  • 详情展示：当前状态、提交 / 开始 / 结束时间、资源分配结果、退出码、标准输出与标准错误。
  • 日志来源为调度器输出文件 假设 平台可读取调度器的输出路径。
  • 列表与详情的刷新频率、日志的截断上限：TBD。
结果与状态变化
只读，不改变作业状态。
权限
普通用户仅见自己的作业；账户负责人可见本账户全部；成本管理员与平台管理员可见全部。

FR-04 作业操作：取消与重跑 P1

目的
支持对提交错误的作业及时止损与重试。
触发
用户在作业详情页选择「取消」或「重跑」。
处理规则
  • 取消：仅「排队中 / 运行中」可取消，需二次确认；取消后状态为「已取消」终态。
  • 取消的计量边界：已消耗的资源仍计入用量（见 FR-06），不做免除。
  • 重跑：以原参数创建一个新作业，原作业记录保留不变；重跑同样受配额校验。
异常
调度器取消失败（作业已结束）：以调度器实际状态为准刷新为终态，并提示用户。

FR-05 配额管理 P0

目的
把「谁能用多少」从口头约定变成系统约束，并在超限时提前拦住。
触发
账户负责人（或平台管理员）为账户设置 / 调整配额。
处理规则
  • 配额维度至少包含：核时、GPU 时、并发作业数。各维度上限值与统计周期 TBD。
  • 校验时机为提交时（前置拦截），而非运行中中断。
  • 额度是否在账户内按成员再分配：TBD。
  • 超限后的行为（拒绝提交 / 允许排队但不启动 / 允许超用并记账）三选一：TBD。本 PRD 的 P0 主线按「拒绝提交」编写，若改为其他策略需同步修订 FR-02 的校验规则。
结果与状态变化
配额变更即时生效；账户页展示各维度的已用 / 上限 / 剩余，并提供可解释的剩余量。
异常
调低配额至低于当前已用量：允许保存，但需明确提示「已超用」，且在该周期内不允许新提交。

FR-06 用量计量 P0

目的
把作业的实际消耗变成可归属、可复算的数据，这是成本核算的唯一数据源。
触发
作业进入终态后由平台采集。
处理规则
  • 以作业为最小计量单位，记录资源维度与数量。假设 调度器提供作业级用量（如核时、GPU 时）。
  • 计量起止点：从作业实际开始运行到结束；排队时长是否计入 TBD。
  • 取整规则（按分钟 / 按小时向上取整等）TBD。该规则必须在定价之前定稿，否则账单金额无法复算。
  • 是否计量存储占用（作业输出落盘量）TBD。
  • 用量记录一经生成不可修改；确有错误只能通过「调整项」冲正（见 FR-08）。
结果与状态变化
生成该作业的用量记录，并计入所属账户当期账单草稿。
异常
计量数据缺失（调度器未返回或作业被强制清理）→ 该作业标记「用量待补」，进入待处理列表并通知成本管理员；在其补齐前，当期账单不得关账。

FR-07 定价管理 P1

目的
用可维护的费率表把用量折算为内部成本，支持费率变化可追溯。
触发
成本管理员新增或调整单价规则。
处理规则
  • 单价规则由「适用维度 + 适用队列 + 单价 + 生效区间」构成；同一维度同一队列在同一时间只能有一条生效规则。
  • 费率变更只影响生效区间之后产生的用量，不回算历史账单。
  • 是否需要阶梯价 / 折扣 / 不同队列差异化费率：TBD。P0 按「一维度一费率」编写。
  • 单价数值由业务提供，本文不写具体数字。
异常
某维度尚无生效费率时产生用量 → 该部分用量标记「未定价」，不得以 0 计入账单；并在出账前提示成本管理员补齐。

FR-08 账单与对账 P1

目的
把用量沉淀为可核对、可追溯、可申诉的周期性成本结果。
触发
账期结束由系统出账；或账户负责人提出异议。
处理规则
  • 账单按「账户 × 账期」生成，包含各维度用量、适用费率、金额小计，并可下钻到具体作业。
  • 出账后金额固化；此后产生的用量计入下一账期。
  • 异议流程：账户负责人发起 → 成本管理员处理 → 以「调整单」形式冲正或补记 → 关账。调整必须留痕（谁、何时、为什么）。
  • 因内部成本核算定位，本期不涉及付款、发票、催收；「欠费停服」能力不做。
异常
存在「用量待补」或「未定价」记录时，账单不得关账，只可停留在草稿 / 有异议状态。

FR-09 用量与成本报表 P1

目的
让账户负责人与成本管理员能按维度查看趋势并导出。
触发
用户打开报表页或执行导出。
处理规则
  • 可按账户、队列、时间范围、资源维度聚合查看用量与成本。
  • 导出格式 TBD（CSV / Excel）。
  • 可见范围遵循 第 5 节 的权限矩阵。
结果与状态变化
纯只读，不改变任何业务状态；导出动作需记入审计。

FR-10 通知与审计 P1

目的
让关键事件可被及时感知、关键动作可被追溯。
触发
由系统事件驱动（作业终态、配额告警、出账、用量待补），无用户手动触发入口。
处理规则
通知至少覆盖：作业终态、配额接近上限、账单出账、用量待补需人工处理。渠道（站内 / 邮件）与频率 TBD。
审计至少记录：配额调整、费率变更、账单调整、集群凭据变更。审计记录需包含操作者、时间、变更前后值与原因，且不可被业务角色删除。
结果与状态变化
通知产生送达记录（成功 / 失败），失败需可重发；审计记录生成后只可追加、不可修改或删除。

5.2 计量与计费口径（唯一口径）

为避免同一条规则在多处重复定义，以下口径为全平台唯一来源，各 FR 引用而非重述：

  1. 计量对象：作业级用量；账户是唯一归属单元。
  2. 计量时点：作业进入终态后采集；采集到的记录不可变更。
  3. 折算：金额 = 用量 × 对应维度生效单价；同一维度同一队列同一时间仅一条生效费率。
  4. 未定价用量：不得按 0 计入，必须阻断关账。
  5. 更正方式：仅允许通过调整单冲正，禁止直接改历史记录。

5.3 关键异常与恢复

异常系统行为用户可执行的恢复动作
配额不足拒绝提交，不落作业调整资源需求，或联系账户负责人提额
调度器不可达该集群队列从提交列表移除选择其他集群，或稍后重试
